# Implementation Plan: Conversation Persistence Logic (Chunk 7)

## Summary

Implement database operations for creating, fetching, and storing conversation history in a stateless way. This includes creating the Conversation and Message models (prerequisite from Chunk 2), and implementing four persistence functions: `get_or_create_conversation`, `fetch_history`, `store_user_message`, and `store_assistant_response`. All functions use async database operations and enforce user isolation.

## Implementation Components

### Component 1: Database Models

**File**: `backend/src/models/conversation.py`

**Purpose**: Define SQLModel classes for Conversation and Message entities.

**Contents**:
- `MessageRole` enum (user, assistant)
- `Conversation` model with user_id, timestamps, messages relationship
- `Message` model with conversation_id FK, role, content, tool_calls, created_at

**Dependencies**: SQLModel, SQLAlchemy func for server timestamps

**Acceptance Criteria**:
- [ ] Models can be imported without circular dependencies
- [ ] Tables can be created in database
- [ ] Relationship navigation works bidirectionally
- [ ] Indexes are created for performance

### Component 2: Database Initialization Update

**File**: `backend/src/database.py`

**Purpose**: Update init_db to include new models in metadata.

**Changes**:
- Import Conversation and Message in init_db()
- Ensure SQLModel.metadata.create_all includes new tables

**Acceptance Criteria**:
- [ ] Running init_db creates conversations and messages tables
- [ ] Foreign key constraints are properly created

### Component 3: Persistence Functions

**File**: `backend/src/persistence.py`

**Purpose**: Implement the four persistence functions defined in the spec.

**Functions**:

1. `get_or_create_conversation(session, user_id, conversation_id)` → Conversation
   - Create new if None or invalid
   - Return existing if valid and owned by user
   - User isolation enforced

2. `fetch_history(session, conversation_id, user_id, limit=30)` → list[dict]
   - Fetch N most recent messages
   - Return in chronological order
   - Include role, content, created_at, tool_calls
   - Return empty list for invalid/unauthorized access

3. `store_user_message(session, conversation_id, user_id, content)` → Message
   - Validate conversation ownership
   - Create Message with role=USER
   - Raise ValueError if invalid

4. `store_assistant_response(session, conversation_id, user_id, content, tool_calls)` → Message
   - Validate conversation ownership
   - Create Message with role=ASSISTANT
   - Serialize tool_calls to JSON
   - Raise ValueError if invalid

**Acceptance Criteria**:
- [ ] All functions are async
- [ ] All functions include user_id validation
- [ ] Functions do not commit transactions (caller responsibility)
- [ ] Type hints on all parameters and return values

### Component 4: Unit Tests

**File**: `backend/tests/test_persistence.py`

**Purpose**: Verify persistence functions work correctly.

**Test Cases**:
- get_or_create_conversation: create new, get existing, user isolation
- fetch_history: chronological order, limit applied, empty list cases
- store_user_message: success, ownership validation
- store_assistant_response: success, tool_calls serialization

**Acceptance Criteria**:
- [ ] All acceptance scenarios from spec covered
- [ ] User isolation explicitly tested
- [ ] Edge cases (empty content, None tool_calls) tested
